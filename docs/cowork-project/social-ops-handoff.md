Redirect URIs for the platform apps: https://socialops.inglelandi.com/oauth/{meta,tiktok,google}/callback.

.env choices: DB_CONNECTION=mariadb (Plesk's database), QUEUE_CONNECTION=database and CACHE_STORE=database because Plesk has no Redis (Horizon unused), FILESYSTEM_DISK=local with signed links for the pilot, mail through a Plesk mailbox over SMTP. Two per-minute Plesk scheduled tasks run `artisan schedule:run` and `artisan queue:work --stop-when-empty --max-time=55`. Steps in docs/pilot-setup.md (PRs #15, #16, #17 merged 2026-11-03).

Quirks hit on the first deploy (2026-11-03):
- The web server is LiteSpeed, not Apache. PHP must run as "FPM application served by Apache" or "FastCGI application"; "served by nginx" makes every PHP request a 403 with "MIME type application/x-httpd-php ... does not allow serving as static file".
- Plesk's own 404 page means the document root is not public/; Plesk's 403 page with static files working means the PHP handler problem above.
- Plesk CLI PHP prints harmless memcached.so warnings; no nano (.env now edited on the Settings page, which also rebuilds the config cache).
- Front-end assets: no Node on the server, so build here (`npm ci && npm run build`), zip public/build as build.zip and attach it; Panos extracts it in Plesk File Manager inside public/. Redo after every front-end change.
- Live since 2026-11-03 17:53 (first answer 16:38 after a Vite manifest error and the build zip). APP_DEBUG must be false in production; delete public/index.html (Plesk's default page dropped into public/).
- key:generate was run twice before go-live (harmless then); never again after accounts are connected, it breaks encrypted tokens and signed links.

**Why:** A later thread helping with the server must not rediscover these.
**How to apply:** Give Panos one short command block per step with full paths; check the Plesk Logs page error line before guessing. See [[social-ops-project]] for the project itself.
